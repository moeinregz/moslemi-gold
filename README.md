# طلا فروشی مسلمی — فروشگاه آنلاین طلا (MVP)

React 18 (Vite) + Node.js (Express) + SQLite (better-sqlite3)

ظاهر سایت همان طراحی فعلی (`طلا فروشی مسلمی.html`) است که فروشگاهی شده و پنل مدیریت چندکاربره دارد.

## راه‌اندازی

```bash
cd mosallami-gold
npm install
cp .env.example .env      # SITE_URL، رمز مدیر کل و پورت را عوض کنید
npm run build             # ساخت رابط React در dist/
npm start                 # http://localhost:4000
```

- دیتابیس `data/shop.db` بار اول خودکار ساخته و با دسته‌ها و چند محصول نمونه پر می‌شود.
- پنل: `/admin` — ورود اول با `ADMIN_USERNAME` / `ADMIN_PASSWORD` از `.env` (پیش‌فرض `admin` / `admin123`). بلافاصله رمز را از «رمز عبور» پایین منو عوض کنید.
- توسعه: `npm run dev` (API روی ۴۰۰۰ و رابط با hot-reload روی ۵۱۷۳).
- تست کامل جریان خرید و پنل: `npm test`.

> روی VPS اجرا شود، نه هاست serverless (مثل Vercel): SQLite و عکس‌های آپلودی روی دیسک ذخیره می‌شوند.
> از پوشه‌ی `data/` (دیتابیس + عکس‌ها) روزانه بکاپ بگیرید.

### انتشار روی سرور (نمونه)

```bash
npm ci && npm run build
npx pm2 start npm --name mosallami -- start && npx pm2 save
```

nginx جلوی آن با SSL (`proxy_pass http://127.0.0.1:4000;`، `client_max_body_size 100m;` برای آپلود چند عکس) و در `.env` مقدار `TRUST_PROXY=1`.
`SITE_URL` باید دامنه‌ی واقعی با https باشد؛ آدرس بازگشت درگاه، فید ترب و سایت‌مپ از آن ساخته می‌شوند.

## انتشار روی لیارا (پیشنهادی)

فایل `liara.json` آماده است (Node 22، پورت ۴۰۰۰ و دیسک `data` برای دیتابیس و عکس‌ها).

1. در پنل لیارا یک برنامه‌ی **Node.js** با نام `moslemi-gold` بسازید (اگر نام دیگری گذاشتید، `app` را در `liara.json` عوض کنید).
2. در بخش «دیسک‌ها» یک دیسک با نام `data` بسازید.
3. در «متغیرهای محیطی» این‌ها را بگذارید: `SITE_URL=https://دامنه‌ی-شما`، `ADMIN_USERNAME`، `ADMIN_PASSWORD`، `TRUST_PROXY=1`.
4. دیپلوی: `npm i -g @liara/cli` و بعد `liara login` و `liara deploy` داخل همین پوشه (یا اتصال گیت‌هاب در پنل لیارا).
5. دامنه را در بخش «دامنه‌ها» وصل و SSL را فعال کنید.

## انتشار با داکر روی هر سرور

```bash
cp .env.example .env    # مقادیر را پر کنید
docker compose up -d --build
```
دیتابیس و عکس‌ها در پوشه‌ی `data/` کنار پروژه می‌مانند.

> **Vercel مناسب این پروژه نیست:** سرور همیشه‌روشن و دیسک ماندگار ندارد (دیتابیس و عکس‌ها پاک می‌شوند) و درگاه‌های ایرانی معمولاً درخواست از سرور خارج از ایران را قبول نمی‌کنند.

## امکانات

**فروشگاه**
- صفحه‌ی اول با همان طراحی، نوار قیمت زنده (۱۸ عیار، ۲۴ عیار، مثقال، سکه‌ها)، دسته‌ها و «مجموعه منتخب» از دیتابیس
- فروشگاه با فیلتر دسته، جستجو و مرتب‌سازی؛ صفحه‌ی محصول با گالری چند عکس و **ریز قیمت** (طلا + اجرت + سود + مالیات + سنگ)
- سبد خرید، ارسال پستی یا تحویل حضوری، هزینه‌ی ارسال و ارسال رایگان بالای یک مبلغ
- **همه‌ی قیمت‌ها سمت سرور و با نرخ لحظه‌ای حساب می‌شوند**؛ قیمت از مرورگر قبول نمی‌شود
- پیگیری سفارش با کد + موبایل، پرداخت دوباره‌ی سفارش ناموفق
- حساب مشتری (ثبت‌نام با موبایل و رمز)، ذخیره‌ی نشانی، لیست سفارش‌ها؛ سفارش‌های مهمان قبلی با همان شماره خودکار به حساب وصل می‌شوند

**قیمت‌گذاری طلا** (`server/pricing.js`)
```
ارزش طلا = وزن × نرخ هر گرم در آن عیار      (نرخ عیار k = نرخ۱۸ × k/18)
اجرت    = ارزش طلا × ٪اجرت
سود     = (ارزش طلا + اجرت) × ٪سود
مالیات  = (اجرت + سود) × ٪مالیات بر ارزش افزوده
قیمت    = طلا + اجرت + سود + مالیات + سنگ      (گرد به ۱۰۰۰ تومان)
```
تخفیف روی اجرت و سود اعمال می‌شود. برای سکه و شمش حالت «قیمت ثابت» هست.
با عوض کردن «نرخ روز طلا» در پنل، قیمت همه‌ی محصولات در سایت، سبد و فیدها همان لحظه عوض می‌شود.

**پنل مدیریت** (`/admin`)
- داشبورد: فروش ۲۴ ساعت و ۳۰ روز، نمودار ۱۴ روز، سفارش‌های منتظر، موجودی کم، پرفروش‌ها، کاربرانِ آنلاین
- محصولات: افزودن/ویرایش/حذف، **آپلود چند عکس با کشیدن و رها کردن**، انتخاب عکس اصلی و ترتیب، پیش‌نمایش زنده‌ی قیمت، ویرایش سریع موجودی/فعال/ویژه از لیست
- دسته‌بندی‌ها، نرخ روز طلا و نوار قیمت، سفارش‌ها (تغییر وضعیت، کد رهگیری پست، یادداشت داخلی، تاریخچه، چاپ)، مشتری‌ها
- تنظیمات فروشگاه، ارسال و درگاه‌ها (با دکمه‌ی «تست اتصال»)
- **کاربران پنل و نقش‌ها**: مدیر کل، مدیر فروشگاه، کارشناس محصولات، پشتیبان سفارش‌ها، یا «سفارشی» با تیک زدن دسترسی‌ها
- **گزارش فعالیت**: هر کار (ویرایش محصول، تغییر وضعیت سفارش، تغییر نرخ، ورود…) با نام شخص ثبت می‌شود

**کار هم‌زمان چند نفر**
- هر نفر نام کاربری و نشست جداگانه دارد؛ تعداد کاربر و نشست هم‌زمان محدودیتی ندارد
- SQLite در حالت WAL: خواندن و نوشتن هم‌زمان بدون قفل
- **قفل خوش‌بینانه**: اگر دو نفر هم‌زمان یک محصول یا سفارش را ویرایش کنند، دومی به‌جای پاک کردن تغییرات اولی پیام «همین الان توسط فلانی تغییر کرده» می‌گیرد
- غیرفعال کردن یا عوض کردن رمز یک کاربر او را از همه‌ی دستگاه‌ها خارج می‌کند؛ دکمه‌ی «خروج اجباری» هم هست
- حداقل یک مدیر کل فعال همیشه باقی می‌ماند

**امنیت**: رمزها با scrypt، کوکی HttpOnly + SameSite، محافظت CSRF با هدر، محدودیت تلاش ورود (۸ بار در ۱۵ دقیقه)، بررسی امضای واقعی فایل عکس (نه فقط پسوند)، حداکثر ۸ مگابایت برای هر عکس.

## درگاه پرداخت

همه از «پنل ← تنظیمات و درگاه» تنظیم می‌شوند. مبلغ به ریال ارسال می‌شود.

| درگاه | فایل | لازم |
|---|---|---|
| زرین‌پال (API v4) | `server/payments/zarinpal.js` | مرچنت کد — حالت sandbox هم دارد |
| زیبال | `server/payments/zibal.js` | مرچنت (برای تست: `zibal`) |
| پرداخت حضوری / کارت‌به‌کارت | — | سفارش با «در انتظار تأیید پرداخت» ثبت و موجودی رزرو می‌شود |
| درگاه آزمایشی | `server/payments/index.js` | **قبل از فروش واقعی خاموش شود** |

جریان: ثبت سفارش ← درگاه ← بازگشت به `/api/payment/callback/{درگاه}` ← verify ← کم شدن موجودی ← صفحه‌ی نتیجه.
اگر پرداخت دیرتر از مهلت (پیش‌فرض ۳۰ دقیقه) تأیید شود، سفارش باز هم پرداخت‌شده ثبت می‌شود. اگر هم‌زمان موجودی تمام شده باشد، هشدار در یادداشت داخلی سفارش ثبت می‌شود.
برای اضافه کردن درگاه دیگر (سامان، ملت، آیدی‌پی و…) یک فایل با همان سه تابع `start`، `verify` و `test` بسازید و در `GATEWAYS` اضافه کنید.

## اتصال به ترب و پلتفرم‌های فروش

در «پنل ← کانال‌های فروش» آدرس‌ها آماده‌ی کپی هستند:

| پلتفرم | آدرس | توضیح |
|---|---|---|
| **ترب** | `/torob/products` | وب‌سرویس محصولات با خروجی `torob_api_v3` (GET/POST، صفحه‌بندی، `page_urls`/`page_uniques`)، توکن اختیاری. صفحه‌ی هر محصول هم متاتگ‌های `product_id`، `product_price`، `product_old_price`، `availability`، `guarantee` و JSON-LD دارد که خزنده‌ی ترب و گوگل بدون اجرای جاوااسکریپت می‌خوانند. |
| **ایمالز** | `/emalls/products` | JSON صفحه‌بندی‌شده (`page`، `item_per_page`)، توکن اختیاری |
| **گوگل شاپینگ** و مقایسه‌گرهای XML | `/feeds/products.xml` | فید استاندارد Google Merchant |
| **دیجی‌کالا، اسنپ‌شاپ، شیپور و…** | `/feeds/products.csv` | خروجی اکسل برای ورود گروهی در پنل فروشندگی |
| **باسلام** | ارسال مستقیم با API | توکن شخصی، تست اتصال، جستجوی دسته، ارسال تکی یا همه‌ی محصولات (عکس اصلی هم آپلود می‌شود) |
| گوگل سرچ | `/sitemap.xml`، `/robots.txt` | |

مراحل ترب: در panel.torob.com ثبت‌نام و تأیید دامنه ← آدرس `https://دامنه/torob/products` را در بخش وب‌سرویس وارد کنید.
**نکته:** مستندات رسمی ترب و ایمالز از محیط توسعه در دسترس نبود؛ ساختار خروجی بر اساس نسخه‌ی رایج وب‌سرویس آن‌ها نوشته شده. اگر پشتیبانی ترب/ایمالز نام فیلدی را متفاوت خواست، فقط کافی است همان بخش در `server/channels/feeds.js` را اصلاح کنید.
چون قیمت طلا روزانه عوض می‌شود، ترب و ایمالز قیمت را هر بار از فید تازه می‌گیرند؛ برای باسلام بعد از تغییر نرخ، دکمه‌ی «ارسال / به‌روزرسانی همه» را بزنید.

## ساختار

```
server/index.js          Express، سرو React، تزریق متاتگ محصول برای ترب/گوگل
server/db.js             اسکیمای SQLite و داده‌ی اولیه
server/pricing.js        فرمول قیمت طلا و نوار قیمت
server/orders.js         محاسبه‌ی سبد، ثبت سفارش، پرداخت، موجودی
server/auth.js           رمز، نقش‌ها و دسترسی‌ها  ·  sessions.js  نشست‌ها و گزارش فعالیت
server/routes/public.js  API فروشگاه و حساب مشتری
server/routes/admin.js   API پنل مدیریت (+ آپلود عکس)
server/payments/         زرین‌پال، زیبال، آزمایشی
server/channels/         فیدها (ترب، ایمالز، XML، CSV، سایت‌مپ) و باسلام
client/src/store/        صفحات فروشگاه
client/src/admin/        پنل مدیریت
test/flow.test.js        تست کامل: چند کاربر هم‌زمان، دسترسی‌ها، قفل ویرایش، آپلود، خرید، فیدها
data/                    دیتابیس و عکس‌ها (در git نیست؛ بکاپ بگیرید)
```
